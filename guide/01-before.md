# 01 · The week before

> Your first hackathon is lost or won before it starts. Almost nobody believes this until it happens to them.

## A week out: get the machine ready

Do this on a normal day, on good Wi-Fi, with time to fix things.

- [ ] **Run the setup guide for your OS** — [Windows](../setup/windows.md) / [macOS](../setup/macos.md) / [Linux](../setup/linux.md)
- [ ] `git --version`, `node -v`, `python --version` all work in a **fresh** terminal
- [ ] Create a GitHub account (use your real name — judges and recruiters look)
- [ ] Set up SSH keys or `gh auth login` so you're not typing passwords at 3am
- [ ] Configure git identity: `git config --global user.name` / `user.email`
- [ ] Deploy a throwaway "hello world" to **Vercel / Netlify / Cloudflare Pages** and open the URL on your phone
- [ ] Install your editor + extensions ([setup/editors.md](../setup/editors.md))
- [ ] Create accounts on whatever the event uses: Devpost, MLH, Discord, Slack
- [ ] Grab student freebies → [resources/free-stuff.md](../resources/free-stuff.md)

**The deploy test matters most.** If you have never pushed something live, do it now — not at hour 30 with three teammates watching.

## Two days out: get the plan ready

- [ ] Read the event page **properly**: schedule, rules, judging criteria, prize tracks, submission deadline (usually *before* the demo, and always earlier than you think)
- [ ] Note the **submission requirements** — repo link? video? Devpost form? Some events require a 2-minute video you must record *during* the event
- [ ] Check the **allowed stack**. Some sponsor tracks require a specific API or cloud
- [ ] Agree a **team channel** and put the event link, repo link, and deadlines pinned in it
- [ ] Decide who does what, roughly. See [04-git-with-a-team.md](04-git-with-a-team.md)

## The night before

- [ ] Charge everything. Bring the charger anyway.
- [ ] Pack: laptop, charger, **extension cord / power strip**, headphones, mouse, water bottle, snacks, hoodie (venues are freezing), painkillers
- [ ] Download offline copies of any docs you rely on
- [ ] Set up a repo with a README already written (use [templates/README.template.md](../templates/README.template.md))
- [ ] **Sleep 7+ hours.** This is a performance event, not an endurance contest.

## What "ready" actually looks like

You can, from a blank folder, in under 5 minutes:

1. create a repo and push it,
2. start a local dev server,
3. deploy it to a public URL.

If you can do that, you're more prepared than half the room.
