The short version

If you read nothing else, read these seven lines.

  1. Set up a week early. Test that you can deploy something to a public URL before you arrive.
  2. Scope for a 2-minute demo. One feature that makes people lean in beats ten that half-work.
  3. Deploy on hour one. A working URL changes how the whole team behaves.
  4. Commit early, commit often. A broken main branch at hour 40 is how teams lose.
  5. Never commit secrets. .env stays out, .env.example goes in.
  6. Build for the rubric. Know what's being scored, and use the sponsor's API if there's a prize.
  7. Sleep. A rested team beats a 36-hour-awake team every time.

⚠️ The installers are dry-run by default

./scripts/install.sh prints every command and changes nothing. Add --apply when you're happy with the plan. It never uses sudo, never deletes files, and backs up any config it replaces.
